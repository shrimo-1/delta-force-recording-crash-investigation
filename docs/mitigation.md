# 保留洲洲时刻的规避与验证

## 目标

保留自动录制、事件解析、NVENC、音频和视频剪辑，不通过修改游戏文件、注入拦截、TDR 注册表或替换 DLL 来规避。

## 方案 A：只移除第二套覆盖层

1. 洲洲时刻保持开启；
2. 捕获模式使用进程捕获；
3. 编码器保持 NVENC；
4. 关闭 NVIDIA App 游戏内覆盖与游戏滤镜；
5. 关闭其他帧率、滤镜、监控和录制覆盖层；
6. 完整退出 WeGame 后冷启动；
7. 完成第一局并停留到结算；
8. 连续执行三次独立冷启动。

期间不要同时调整 EXPO/XMP、PBO、画质、编码器或捕获模式，否则无法判断哪个变量起作用。

### 通过标准

- 录制视频画面、声音与封装正常；
- 结算时无冻结；
- 无新 CrashSight DMP；
- 无新增 `nvlddmkm 153` 或 WATCHDOG `0x141`；
- 无 `graphics-hook64+0x1AB42/+0x1AB89`。

若通过，说明 NVIDIA 覆盖层是重要促进因素，但不等于腾讯钩子已经安全。

## 方案 B：保留录制，仅关闭腾讯游戏内提示浮层

客户端行为调查表明，录制能力与游戏内浮层由独立配置控制。向腾讯申请账号/灰度配置：

```text
enableSDK=true
enableRecord=true
overlayEnable=false
```

该配置应保留录制和剪辑，但不建立浮层 IPC，不向游戏发送 `window=3` / `record_success.png`。

### 通过标准

除方案 A 的标准外：

- 录制文件仍正常生成；
- 日志不再出现成功图片消息；
- 游戏内不再显示开始/停止/成功图片提示；
- 录制管理界面仍可访问生成的视频。

## 不建议的绕行

- 修改 `app.asar`、字体校验文件或 `graphics-hook64.dll`；
- 修改游戏目录 ACL；
- 注入拦截命名管道；
- 增大 TDR 延时；
- 同时切换多个 BIOS/驱动/画质选项。

这些方法要么触及完整性与反作弊边界，要么只是延长挂起时间，不能修复错误的资源生命周期与空指针处理。
